# 旧项目复用：准入规则与判断

> 状态：草案，2026-10-13 修订。遵守 `00-product.md` §5.5、§5.9；`01-acceptance.md` §5。
> 本文回答：旧项目 `/Volumes/ExtSSD2601/Docfit` 里的东西，凭什么能进新系统；目前每一项的判断。
> **不回答**：新系统的结构（`design/01-code-layout.md`）。

## 1. 默认不拿

旧项目的问题是架构摇摆和不断叠加（P01、P03）。它的代码大多带着旧架构的形状，拿过来就是把旧问题带回来。所以**默认不拿**，每一项都要通过准入。

## 2. 准入条件（全部满足才拿）

1. **形状对**：符合新设计的角色边界和交接格式，不需要为它改新设计。
2. **体量对**：大小与它要做的事相称。用 1000 行去读一个 YAML，说明它带着旧机制，不拿。
3. **独立**：只依赖极少的辅助代码，能单独拷出来运行。旧包之间有循环引用，只能按文件拷。
4. **在新环境里验证过**：带上测试，在新仓库重新跑。旧项目里写的"已通过"不算数（P17）。
5. **拿值，不拿机制**：数据类资产只取其中已被产品负责人确认的**取值**，不沿用它的格式和概念。

## 3. 逐项判断

| 候选 | 判断 | 理由 |
|---|---|---|
| 通用样式预设 v1 的**取值**（字体、字号、缩进等） | **拿值** | 你在 2026-08-11 验收过的领域决定，重新定一遍是浪费 |
| 通用样式预设 v1 的**格式**（属性画像、VALUE/NONE/N/A、44 个角色、版面角色） | 不拿 | 旧样式合同模型的产物，比新设计需要的重得多（§5.9） |
| 预设读取代码 `presets.py` + `profiles.py`（1239 行） | 不拿 | 不满足条件 2 |
| 字段注册表 v0.5（54 个字段） | **只作参考清单** | 含大量封面字段（新设计里封面原样保留，用不到）和个别学校的项目（如二维码页）。各阶段只挑用得到的字段，`id` 可以沿用 |
| 生效格式解析 `styles/resolver.py`（648 行） | **候选，S0 再定** | 只读、只依赖一个辅助文件，在南农模板上能跑通（条件 3 满足）。但它的定位写法和错误约定是旧的，且超过 400 行。S0 写 Tool 时，与自写的版本在同一批对象上对比结果，再决定 |
| Docker 版 LibreOffice 渲染器 | **候选，S0 再定** | 叶子工具，不带架构；需要在本机实测 |
| PDF 转图片、docx 完整性检查 | **候选，S0 再定** | 同上 |
| 领域知识包 v1（约 90 行） | 写提示词时**参考** | 不直接作为提示词 |
| 其余全部（应用层、观测、模板变更、内容提取、样式合同等） | 不拿 | 绑定旧架构 |

## 4. 怎样执行

- 被判"候选"的，在 S0 用到它的那一步，按 §2 逐条核对后再搬入，并在本文更新判断。
- 被判"拿值"的，把取值抄进新的数据表，标明来源和验收日期。
