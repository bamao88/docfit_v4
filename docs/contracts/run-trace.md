# 运行轨迹（Run Trace）

> 状态：草案 v0。遵守 `00-product.md` §5.3；设计见 `design/06-quality.md` §4。
> 本文只回答：产品每次运行要记录什么，供全链路可视化和链路分析使用。
> 生产者：产品运行时（`harness/loop.py`、各步骤）。消费者：`docfit-evals` Skill。产品本身不读它。

## 1. 为什么要有

产品 AI 的判断错在哪里，只看最终 Word 看不出来。轨迹记录每一步"AI 看到了什么、想了什么、说了什么、被怎样纠正"，让人和分析代理能沿着链路找到第一个出错的地方。

它有明确的使用者（全链路视图、链路分析），不是为观测而观测（`design/06-quality.md` 约束 5）。

## 2. 每一步：`runs/<任务>/steps/<步骤>/log.json`

| 字段 | 含义 |
|---|---|
| `step`、`status` | 步骤名；ok / fallback / unresolved / fail |
| `inputs`、`outputs` | 产物名与哈希 |
| `duration_ms` | 耗时 |
| `counts` | 处理的对象数、降级数、未决数 |
| `calls` | 本步骤的 AI 调用 id 列表（AI 步骤才有） |

## 3. 每次 AI 调用：`runs/<任务>/steps/<步骤>/agent/<调用 id>.json`

| 字段 | 含义 |
|---|---|
| `scope` | 判定的对象范围（如某个单元） |
| `view` | 给产品 AI 看的视图原文 |
| `prompt_modules` | 用了哪些提示词模块及其版本 |
| `rounds` | 每一轮：思考（后端提供时记录）、结构化输出、校验错误、回发的反馈 |
| `final` | 每个对象的最终结论，及来源：首轮接受 / 第 N 轮修正 / 降级 |
| `usage` | 用量与耗时 |
| `cache` | 命中缓存还是真实调用 |

## 4. 规则

1. 产品每次运行都记录，本地落盘，成本可忽略。
2. 只记录，不分析；分析在 Skill 里做。
3. 包含学生论文内容，只留在本地任务目录，不进 git，不上传。
4. 思考内容能否取到取决于模型后端；取不到时记为空，不让产品 AI 额外输出理由来填补（P08）。
