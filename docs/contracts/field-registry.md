# 字段注册表（Field Registry）

> 状态：草案 v0。遵守 `00-product.md` §3.1。
> 本文只回答：字段注册表的形态与规则。**不回答**：具体有哪些字段（在 `data/registry/` 里）、骨架（`contracts/unit-skeleton.md`）。
> 使用者：A（骨架引用字段和角色）、B（区域与角色判定）、C（按名字对接）。

## 1. 组成

| 文件 | 内容 |
|---|---|
| `data/registry/fields.yaml` | **字段**：只出现一次的内容，如论文题目、中文摘要、关键词 |
| `data/registry/roles.yaml` | **结构角色**：可重复的内容，如各级标题、段落、图、表、公式、题注 |

## 2. 每一项的信息

| 项 | 含义 |
|---|---|
| `id` | 稳定的英文名，跨版本不变 |
| `name` | 中文名 |
| `meaning` | 一句话含义，供提示词使用 |
| `enabled` | 仅角色：当前阶段是否启用（S0 只启用标题和段落） |

## 3. 规则

1. 只说"有哪些种类的内容"，不保存内容，不规定必填、位置和顺序（`00-product.md` §3.1）。
2. `id` 只增不改；废弃的标注废弃，不删除。
3. 注册表、骨架、单元类型表、区域表一起构成数据表版本，写入每个产物的通用头。
4. A 和 B 各自独立地用它理解自己的输入；C 只靠 `id` 对接。
