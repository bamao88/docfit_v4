# 单元骨架（Unit Skeleton）

> 状态：草案。遵守 `00-product.md` §3.1、§4.7；决策见 `04-decisions.md` D7。
> 本文只回答：骨架是什么、长什么样、有什么规则、谁用它。**不回答**：A 的流程（见 `modules/A-template-extraction.md`）、各类型的具体槽位内容（见 §5，待做）。

## 1. 是什么

每个"填写"类单元类型，有一份**骨架**：该类单元可能出现的内容的**最大集合**，由若干**槽位**组成，部分槽位可选。

学校的单元只是骨架的一个子集加上各自的格式。例如大多数学校的摘要只有"正文"和"关键词"，个别学校还有标题；骨架包含全部，学校没有的槽位就不出现。

## 2. 为什么需要

| 好处 | 说明 |
|---|---|
| 选项封闭 | AI 的任务从"自由分析"变成"把对象对应到槽位"，适合便宜模型 |
| 提示词变短 | 骨架本身就说明了"这类单元长什么样" |
| 模块 C 与学校无关 | 不同学校的摘要，槽位名字都一样，C 只按槽位名填 |
| 有据可依 | 一个单元能被判为"填写"，前提是存在对应的骨架 |

## 3. 形态

骨架是**数据**，不是代码。每个槽位只有四项信息：

| 项 | 含义 |
|---|---|
| 槽位名 | 稳定，跨学校不变 |
| 种类 | **字段**（只填一次）/ **结构**（可重复，样式来自示例）/ **标签**（学校固定文字）/ **生成**（由 Word 自动生成） |
| 是否可选 | 学校可以没有这个槽位 |
| 引用 | 引用字段注册表中的字段，或引用一个结构角色（如"一级标题"） |

示例（摘要，仅示意形态，不代表最终内容）：

| 槽位名 | 种类 | 可选 | 引用 |
|---|---|---|---|
| 摘要标题 | 标签 | 是 | — |
| 论文题目 | 字段 | 是 | 论文中文题目 |
| 摘要正文 | 字段 | 否 | 中文摘要 |
| 关键词标签 | 标签 | 否 | — |
| 关键词 | 字段 | 否 | 关键词 |

示例（目录，仅示意）：

| 槽位名 | 种类 | 可选 | 引用 |
|---|---|---|---|
| 目录标题 | 标签 | 否 | — |
| 一级条目 / 二级条目 / 三级条目 | 结构 | 二、三级可选 | 目录条目角色 |
| 目录域 | 生成 | 否 | — |

## 4. 规则

1. **小**：每份骨架槽位数保持在个位数到十几个以内。过大会让便宜模型困惑；需要超过时先考虑是否应拆成两个单元类型。
2. **不描述格式**：骨架里不出现字号、字体、缩进等数值。格式永远由代码从原件读取。
3. **不含学校专属槽位**：只收有通用性的内容。个别学校独有的内容，对不上槽位，按"保留"处理。
4. **对不上的对象默认保留**：延续安全下限（`00-product.md` §4.7）。
5. **属于字段注册表体系**：槽位引用的字段含义，只在字段注册表定义一次，骨架不重复定义。
6. **只增不改槽位名**：已被合同引用的槽位名不得重命名；需要变更时新增并标注旧名废弃。
