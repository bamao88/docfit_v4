# 模块 C：填充组装

> 状态：草案，待产品负责人确认
> 遵守 `00-product.md`：§2（C 不重新理解模板和论文）、§3.4（样式角色整体来源）、§4.1、§4.2、§4.3、§4.4、§5。
> 输入格式见 `contracts/fill-contract.md`、`contracts/content-model.md`；代码位置见 `design/01-code-layout.md`。
> 本文**只回答**：流程、每步的输入输出与责任、已识别的风险。**不回答**：缺失策略本身（Q1、Q9、Q10）。

## 1. 目标与边界

把内容模型放进已审核的模板资产，输出一份最终 Word。

- **C 里没有 AI。** 两边的理解已经由 A、B 完成，C 只按字段名、槽位名、角色名对接。
- 不修改模板中槽位之外的任何对象（V2）。
- 所有"对不上"只在 C 处理（`00-product.md` §4.1）。

## 2. 总流程

```
输入：已审核的模板资产 + 内容模型 + 通用样式预设
① 匹配（代码）            字段 ↔ 槽位、角色 ↔ 原型
② 缺口处理（代码）        缺失、多余、暂不支持，按策略表处理并记录
③ 填写计划（代码）        每个槽位放什么、每个内容节点用哪个原型
④ 执行（代码）            在干净模板副本上一次完成全部编辑
⑤ 执行后校验（Checks）    预期 vs 实际
⑥ 交付（外壳）            最终 Word + 界面提示
```

## 3. 各步骤

### ① 匹配
- 单次字段：内容模型的字段名 = 填写合同里槽位引用的字段名，即匹配。
- 正文：每个内容角色找到原型。来源只有两种，**整个角色要么来自学校，要么来自预设**（P15）。
- 输出匹配表：已匹配、模板有槽而内容缺失、内容有而模板无槽、角色无原型。

### ② 缺口处理
- 按 `data/policies.yaml` 查表处理，不在代码里写死。
- S0：策略表还是空的，一律列入内部记录和界面提示，不猜、不丢。

### ③ 填写计划
- 单次字段：槽位 → 文字。
- 正文区域：把内容树展开成序列，每个节点 → （原型槽位、文字、前缀是否使用）。
- **编号前缀**：原型带自动编号时不用学生的前缀；原型没有自动编号时保留学生前缀（章节编号可重新生成，见 Q11）。
- 计划是纯数据，落盘，可单独检查。

### ④ 执行
- 一个编辑会话：填单次字段 → 按序列克隆原型插入正文区域（预设角色用 `materialize` 写入格式）→ 删除用完的原型。槽位的内容控件保留（D15）（`design/02-tool.md` §4）。
- 学生的批注随所在文字一起搬入，原样保留（D16，S1）。
- 每个角色一个处理函数（`fill/handlers/<角色>.py`），S0 只有标题和段落。
- 目录等生成对象不填内容，只保证其机制完好（`00-product.md` §4.2）。

### ⑤ 执行后校验（Checks）
- 预期清单 = 模板对象序列中，每个槽位区域替换为对应内容序列。
- 检查：内容节点逐个出现一次且文字一致（V1、V4）；格式指纹等于对应原型（V3）；槽位外的模板对象不变（V2）；文件可重新打开（V6）。

### ⑥ 交付
- 用户只收到一份 Word（V7）。
- 界面提示：哪些单元按原样保留需手填；哪些内容未处理（S0 中的图、表、公式）。提示的形式待 Q9。
- 内部记录（匹配表、缺口、校验差异）留在任务目录，不交给用户。

## 4. 已识别风险

| # | 风险 | 对策 |
|---|---|---|
| C1 | 模板的章标题是手打编号（原型文字里有"第一章"） | A 把手打编号判为原型的一部分，由合同标出；处理方式在 S0 实测后定 |
| C2 | 每章另起一页靠的是原型里的分页符，而不是段落属性 | 由填写合同说明"重复时是否带分页"（A §5.6），C 照做 |
| C3 | 克隆后编号不连续或不重新开始 | 克隆时保留原型的编号引用；⑤ 检查编号显示文字 |
| C4 | 预设原型的样式与学校样式重名冲突 | 导入预设样式时改名，加固定前缀 |
| C5 | 目录、页码需要在 Word 中更新才正确 | 验收中明确：Word 打开并更新域后检查（V6）；是否自动更新待定 |
