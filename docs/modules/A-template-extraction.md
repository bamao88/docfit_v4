# 模块 A：模板提取

> 状态：草案，待产品负责人确认
> 遵守 `00-product.md`：§2（模块边界）、§3.2（填写合同）、§3.4（样式角色）、§4.3、§4.5（身份）、§4.7（单元处理方式）、§5（横向原则，尤其 5.1、5.2、5.3、5.9）。
> 角色边界（Agent / Harness / Tool / 数据表 / 外壳）见 `02-architecture.md`；骨架见 `contracts/unit-skeleton.md`。
> 本文**只回答**：流程、每步的输入输出与责任、已识别的风险。**不回答**：实现、骨架内容、产品决策。与 `00-product.md` 冲突时，以 `00-product.md` 为准。

## 1. 目标与边界

把一所学校的 Word 原件，变成一项**可复用的模板资产**：一份干净的可填写 Word，加一份说明"哪里填什么"的填写合同。

- 每校做一次；通过入库审核后才能被转换使用（`00-product.md` §2）。
- 不读学生论文。
- 不决定学生内容放在哪（那是模块 C 的事）。

## 2. 总流程

```
① 原件 Word
② 预处理（代码）          对象清单 + source_id + 属性
③ 单元判定（AI）          起点、终点、单元类型
④ 单元检查（代码）        完整、不重、连续；按类型查表得出处理方式
⑤ 分发（代码）            保留 → 直接带到⑧；填写 → 进入⑥（并行）
⑥ 单元内判定（AI）        逐对象 保留/填写/删除
⑦ 判定检查（代码）        完整、唯一；缺的打回，只补缺的
⑧ 执行（代码）            产出干净模板 + 填写合同
⑨ 执行后校验（代码）      对照原件逐对象比对
⑩ 入库审核（人）          单元表 + 样式冲突清单
```

每一步的产物落盘，格式固定，可以单独检查和重放（`00-product.md` §5.3）。

## 3. 各步骤

### ② 预处理
- **输入**：Word 原件。
- **输出**：**对象清单**——按文档顺序排列的对象，每个有稳定 `source_id`、文字内容、生效格式、位置信息（所在分节、是否带分页/分节符等）。
- **负责**：代码。
- **要点**：
  - 真正的空对象（无文字，且无图片、域、分页符、分节符、书签、内容控件）不作为独立对象展示，折叠为相邻对象的"前后留白"属性。
  - 附属内容（页眉页脚、脚注）与正文分开归属，不混在同一单元。
  - 代码标出**候选分界点**（分页符、分节符、"目录""摘要"等标题位置），供③参考。
- **完成检查**：清单可以完整还原出原件的文字内容；对象不重不漏。

### ③ 单元判定
- **输入**：对象清单（含候选分界点）。
- **输出**：**单元表**——每个单元的起点 `source_id`、终点 `source_id`、单元类型。
- **负责**：AI（Skill 里写"怎么认"）。
- **规则**：类型只能从**封闭的已登记清单**中选择，认不准选"其他"。AI 可以附一个自由文字名称，**仅作记录**，处理方式一律按"其他"走。

### ④ 单元检查
- **输入**：单元表。
- **输出**：通过的单元表，每个单元带处理方式。
- **负责**：代码。
- **检查**：每个对象恰好属于一个单元；单元连续、有序、不重叠。不通过则打回③，只指出有问题的位置。
- **处理方式**：按类型查表（见 `01-acceptance.md` §2）。"其他"和未登记类型 → 原样保留。判为"填写"的类型必须对应至少一个已登记字段，否则强制降级为原样保留。
- **注意**：只拆**对象清单**，不拆 Word 文件本身。单元只是整份文档里标出的范围，所以空段归属不影响版式。

### ⑤ 分发
- **负责**：代码。
- 原样保留的单元**不进入⑥⑦**，由⑧原样带过。
- 填写类单元并行进入⑥，每个单元加载该类型对应的提示词（由代码选择）。

### ⑥ 单元内判定
- **输入**：单元类型、该单元的**骨架**、该单元所有对象及其属性。
- **输出**：每个对象的判定。同一对象内需要分段时，AI 只说"在哪句话之后拆"，不写字符位置。
- **负责**：AI。
- **骨架**：每个"填写"类单元类型有一份骨架（`contracts/unit-skeleton.md`）。AI 把对象对应到槽位；对不上任何槽位的，默认**保留**。
- **判定的语义**：保留 / 填写 / 删除。其中"填写"有两种：
  - **单次字段**：只填一次，如论文题目、摘要正文。示例文字删除，换成占位。
  - **可重复结构**：示例用来提供样式和结构，如一级标题、示例表格、示例图。**保留其结构与样式，内容换成占位**，供后续填充时克隆。复合对象（表格、图片、公式）整体判定，不判断内部；它们若是示例，则按"可重复结构"处理，而不是删光。
- **角色标注**：对示例对象，AI 指出它是哪个角色的代表（如"一级标题"）。**AI 不描述格式**；格式由代码从该对象读取（见风险 R3、R4）。

### ⑦ 判定检查
- **负责**：代码。
- **检查**：单元内每个对象都有且仅有一个判定；"填写"必须对应已登记字段；拆分点能唯一定位。拆分产生的新 `source_id` 由代码派生。
- **失败处理**：只把有问题的对象发回，附上该对象原文和具体问题，不回显整批输出。同一对象两次修订仍不合法，标为"未决"，继续后续，最终统一呈现给人。

### ⑧ 执行
- **输入**：通过的单元表和判定表，原件。
- **输出**：**干净模板** Word，和**填写合同**（槽位位置、对应字段、样式角色、保留的单元清单）。
- **负责**：代码。
- **原位编辑**：所有单元都在原件上直接编辑，不重建。只做三件事：保留、删除段落内的文字、把示例替换为占位。**不动**分页符、分节符、空段落和单元之间的分隔，不触碰判定范围之外的对象。
- **目录**：目录是"生成对象"，有专门的处理，仍然只用两种处理方式。
  - 原件里已有真实目录域（如南农、北大）：**原位保留**，不重建。
  - 原件里是手打文字（如湖南农大）：AI 只指出哪些示例条目是几级目录；代码从这些条目读出缩进、字体、字号、前导点等**参数**，填入我们自备的标准目录模板，生成真实目录域。这是 A 里唯一允许"创建"而非"编辑"的操作，且参数化、有明确定义。（待确认）
  - 新生成的目录域没有缓存，需要在 Word 中更新一次才显示页码，这是验收需要考虑的现实约束。
- **整段都是说明的段落**：默认**清空文字、保留该段落**，使行数和分页位置与原件完全一致。是否改为整段删除，在⑩ 看页面图后再决定（待定，见 §5）。
- **样式**：每个角色的格式由代码从代表对象读取生效格式；学校没有的角色，用通用预设整体补上，不在角色内混用。

### ⑨ 执行后校验
- **负责**：代码，重读产物，与原件逐对象比对。
- **检查**：
  - 标"删除"的文字确实不在了；
  - 标"保留"的文字确实在，且生效格式与原件一致；
  - 原样保留的单元与原件一致；
  - 所有对象仍可追溯到 `source_id`；
  - 文件可以重新打开，复合对象（目录域、编号、图片关系、内容控件）完整。
- 回执由比对生成，不由执行器自报。

### ⑩ 入库审核
- **负责**：产品负责人，一次性。
- 看两张短清单：**单元表**（每行：类型 + 起始对象前几个字）和**样式冲突清单**（见 R4）。
- 通过后，这所学校的模板资产才可被转换使用。

## 4. 已识别风险（来自旧项目与设计讨论）

| # | 风险 | 对策 | 关联 |
|---|---|---|---|
| R1 | **单元划分错误** | 错误的代价被限制（偏向保留）；给 AI 候选分界点，而不是凭空切；④ 检查完整与连续；⑩ 人审单元表；单元级批注是第一个要测的指标 | P07 |
| R2 | **空行、空白内容被逐个交给 AI 判断；执行时动了结构导致排版变化** | ② 折叠**仅发生在给 AI 看的清单里**，Word 文件不改；带图片、域、分页符等的不算空；Word 文件不物理拆分，只拆清单，空段归属不影响版式；⑧ 原位编辑，不动分页符、分节符、空段落 | P07、P08 |
| R3 | **用文字表达的样式**（如"（三号黑体加粗）"） | 文字描述永远不是样式来源；AI 只判"删除：格式说明"并标出角色代表；格式由代码从原件读取生效格式。示例文字常带灰色或红色的"提示色"，那是示例标记，不是格式，提取时不得带入 | P14 |
| R4 | **同一角色出现多个冲突样式** | 代码为每个对象算生效格式指纹；不一致时取最多的，并列取文档中最早的；绝不在一个角色内混用；冲突记入清单，⑩ 由人指定；该角色在模板中没有对象则整体用预设 | P15 |
| R5 | **对象拆分导致身份漂移** | 新 `source_id` 由代码派生；AI 只说"在哪句话之后拆" | P06 |
| R6 | **AI 变成转写器**（数空格、写转义） | AI 的输出只引用 `source_id` 和可见文字；字符层面的对齐由代码完成 | P02 |
| R7 | **执行不忠实于判断** | ⑧ 只做三种原语；⑨ 逐对象差异比对；回执由差异生成 | P12 |
| R8 | **复合对象只改了可见部分**（目录、编号、域、内容控件）；**示例对象被整体删光，样式丢失** | 复合对象整体判定，不触及内部结构；示例对象按"可重复结构"保留结构与样式，只换内容；⑨ 校验其完整性 | P13 |
| R9 | **门禁增殖** | ④⑦ 只检查"完整、唯一"；新增任何检查，先说明它防的是哪条不变量 | P03 |
| R10 | **调度**：整批重交、串行 | ⑤ 单元并行；⑦ 只补缺的 | P05 |

## 5. 待定事项

与产品决策相关的，见 `04-decisions.md` 的 Q2（要求文件）、Q3（内容边界）、Q4（是否分三种处理方式）、Q5（单元清单）、Q6（手打目录）。本模块自身待定：

1. 各单元类型的骨架内容（`contracts/unit-skeleton.md` §5）。
2. 提示词：共同核心加该类型的骨架。先有黄金批注再写，再用批注测试。
3. 整段说明的处理：清空文字保留段落（默认），还是整段删除。用实验决定：生成两种结果、渲染页面图，由产品负责人判断。实验需包含 C 填充之后的效果：保留的空段在终稿里会变成多余空白，而 C 不重新理解模板，无人清理。
4. 可重复结构中，图片示例如何处理（保留图所在段落与题注格式，去掉图本身），实现时确认。
5. 页眉页脚的归属：② 把它们与正文分开，但 ④ 要求"每个对象恰好属于一个单元"，它们属于哪里、能否含填写槽位（如页眉里的论文题目），未定。
6. 接口要求：填写合同必须说清"哪些对象构成一个可重复的结构"，包括重复时是否带分页，供模块 C 使用。

## 6. 本模块的验收

引用 `01-acceptance.md` §3 第一级与 §4 黄金标准。分阶段度量：

| 阶段 | 度量 | 标准来源 |
|---|---|---|
| ③④ 单元划分 | 与单元级批注一致 | 黄金批注（单元级） |
| ⑥⑦ 单元内判定 | 与片段级批注一致（仅"填写"单元，仅有批注的部分） | 黄金批注（片段级） |
| ⑧⑨ 执行 | 与原件差异比对，零未授权改动 | 原件本身，无需标准 |
| 整体 | 干净模板满足 `01-acceptance.md` §3 第一级各条 | 人工逐页检查 |
