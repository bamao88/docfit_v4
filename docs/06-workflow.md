# 执行与监督

> 状态：草案，待产品负责人确认。遵守 `00-product.md` §5（尤其 5.4、5.5、5.10）。
> 本文回答：AI 怎样执行一件任务、怎样对结果负责；产品负责人怎样随任务监督。**每个会话开工前必读。**
> **不回答**：自查工程怎么实现（`design/06-quality.md`）、做什么阶段（`05-roadmap.md`）。

## 1. 基本立场

- **AI 端到端对结果负责**：不只写完代码，还要用证据证明产品结果是对的。
- **产品负责人通过结果监督**：看 Word 页面和短表，不看代码。
- **监督随任务发生**：没有固定的检查时间。每件任务的开工和收尾，就是监督点。
- **给人看的证据由机器生成**：AI 不能挑选给人看什么，也不能用自己的叙述代替证据。

## 2. 任务的生命周期

任务是执行和监督的基本单位：

```
开工（任务卡）→ 执行 → 收尾（交付回执，机器生成）→ 审计（独立会话）→ 产品负责人裁决
```

阶段关卡 = 该阶段所有任务回执的汇总 + `05-roadmap.md` 的完成条件。

## 3. 开工：任务卡

放在 `docs/tasks/active/<任务 id>.md`，在 `status.md` 登记一行。任务卡只有五项：

| 项 | 内容 |
|---|---|
| 目标 | 一句话 |
| 所在层 | 哪个模块、哪个角色（Agent / Harness / Tool / 数据表 / 外壳） |
| 预期影响范围 | 哪些样本、哪些单元或角色的输出会变 |
| 完成条件 | 记分板上哪些项要变好，哪些项不许退步 |
| 是否触及保护区 | 是则先停下来问（§7） |

**预期影响范围**是监督的关键：收尾时，工具会拿实际变化和它对比（§5）。

## 4. 执行规则

1. 一次只推进一件任务。中途发现的新问题，先登记成新任务，不顺手处理。
2. 问题回到所属层修（`00-product.md` §5.4），不修在现象出现的地方。
3. 改动自上而下同步：改了上层文档，同一件任务里把受影响的下层一起改。
4. 对话中做出的决定，当场记入 `04-decisions.md`。
5. 拿不准时往小处收：范围拿不准先不做；内容拿不准先保留；方案拿不准先做最小实验。
6. 先有证据，再下结论：旧代码、模型能力、方案优劣，都要实测。

## 5. 收尾：调用 `docfit-evals`，生成 Evals 报告

每件任务收尾**必须调用 Skill `docfit-evals`**（`.claude/skills/docfit-evals/SKILL.md`）。它在冻结样本上重放产品全链路，生成一个本地 HTML 报告，路径写进任务卡。AI 只能在报告里补充两样：一段说明，最多三个需要决定的问题。

报告除下表外，还有**全链路**（产品 AI 每一步看到什么、想了什么、输出什么）和**链路分析**（分析代理指出第一个出错的步骤和原因所在的层），见 `design/06-quality.md` §5。

| 栏目 | 内容 | 防什么 |
|---|---|---|
| 记分板前后对比 | 本任务前后，每个样本、每项检查的变化 | 完成度被说高 |
| **变化对照页** | 本任务让哪些输出页面变了：每页并排显示"原件 / 改前 / 改后"。页面由工具对比前后产物自动找出，不由 AI 挑选 | AI 只给人看好的 |
| **范围外变化** | 实际变化中，超出任务卡"预期影响范围"的部分，标红 | 改 A 坏了 B |
| 健康指标变化 | 超过行数上限的文件、检查项数量、文档体量、保护区改动 | 膨胀（P01、P03、P21） |
| 未验证与跳过的项 | 必填；没有写"无" | 把没做的说成做了 |

## 6. Review：审计

- 由 Skill 的第 8 步完成：开一个**全新的、只读的子代理**，不带开发上下文，核对报告和任务卡里的每一句说法是否有证据支持。
- 审计结论显示在报告总览。证据对不上时，任务退回 AI，不交给产品负责人。
- 审计用的提示词在保护区内，AI 不能修改。

## 7. Review：产品负责人的裁决

- **接受**：本次产物成为新基线，任务关闭，任务卡删除，`status.md` 留一行结论。
- **退回**，附原因：被指出有问题的页面加入回归样本，以后每次运行都要通过。
- 基线只在你接受后更新，AI 不能自己移动基线。
- 不需要看代码。看不懂的地方，直接问"这一页为什么变了"。

## 8. 保护区

AI 只能提修改建议，不能直接改：

- `docfit-evals` 的 `standards/`：冻结样本、黄金标准、检查清单与阈值；
- 审计提示词 `prompts/auditor.md`；
- 基线 `runs/baseline/`；
- 本文与 `00-product.md`。

保护机制：用 Claude Code 的权限设置，把这些路径设为对 AI 只读，修改时由系统弹窗请产品负责人批准（待配置，Q15）。

## 9. 必须停下来找产品负责人的情况

- 同一个问题修了 3 次仍然失败；
- 需要修改保护区；
- 记分板退步，且原因不明；
- 回执里出现范围外变化，且无法解释；
- 结果稳定性低于阈值；
- 要做的事超出当前阶段范围，或发现上下层文档冲突。
