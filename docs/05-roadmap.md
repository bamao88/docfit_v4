## 1. 总策略

**先打通一条最薄的端到端路径，再逐步加宽。**

- 目的：在大量投入之前，暴露两类问题——交接格式（A→C、B→C）不可用；便宜模型的判断质量不够。
- 这不是联调（P18）：A、B、C 仍然只通过正式产物交接，互不读对方内部状态。只是每个模块先做最简版本。
- 每个阶段只加一个维度（内容种类、单元种类、学校），出了问题能定位到是哪个维度引入的。

## 2. 阶段

| 阶段 | 加宽的维度 | 样本 | 目标完成度 |
|---|---|---|---|
| **S0 最薄路径** | — | 南农 + student-001 | 单样本端到端通过 |
| S1 正文完整 | 正文里的图、表、公式、题注 | 南农 + student-001～003 | 单校端到端通过 |

学校顺序的理由：南农有真实目录域、单元独立，最干净；湖南农大的特殊点最多，放最后。

## 3. S0 最薄路径

### 范围
- **只有"正文"一个填写单元**，其中只处理**各级标题和正文段落**。
- 其余单元全部原样保留（包括摘要、参考文献、目录）。
- 学生正文里的图、表、公式：S0 不承诺处理，但**必须在 C 的输出里明确列出未处理项**，不能静默丢失（`00-product.md` §4.4）。
- Agent 采用 E1（一次进、一次出），不做反馈轮。

### 步骤
S0 按完整设计（`design/`）搭好全部结构，薄的地方只由数据决定（`design/00-overview.md` §4）。

1. **黄金标准**：南农原件的单元级批注、正文单元的片段级批注（`01-acceptance.md` §4）；student-001 的区域与正文角色标注。
2. **工程骨架**：目录结构、依赖守卫与行数检查、产物读写与通用头、Agent 调用缓存与 replay 测试框架。先于任何业务代码。
3. **Tool**：读取、生效格式、编辑原语、比对；并实测内容控件槽位（`design/02-tool.md` §4）。
4. **交接格式 v0 定稿**：`contracts/` 下的草案 + `data/` 下只含正文的数据表。
5. **A、B 全部步骤**：数据中只有正文进入单元内（区域内）判定。A 与 B 可并行。
6. **C 全部步骤**：处理函数只有标题和段落。
7. **端到端检查**：对照下面的完成条件，并把样本加入 replay 回归测试。

### 完成条件
- 最终 Word 在 Word 中正常打开。
- student-001 正文的所有标题和段落都在，顺序、层级不变（V1、V4 的 S0 范围）。
- 它们的格式等于模板对应角色的格式，学生原格式未渗入（V3 的 S0 范围）。
- 原样保留的单元与原件一致（V2）。
- 每一层产物都落盘，可单独重放。
- 记录度量：A 的单元划分、单元内判定，B 的区域划分、角色判定，各自与黄金标准的一致度。
- **扩展演练**：按 `design/00-overview.md` §3，纸面推演 S1、S2、S3 各要改哪些文件；落在"不改什么"一栏的，先修设计再进 S1。

### 停下来重新评估的条件
- 便宜模型的单元划分或单元内判定明显不可用 → 先回到架构层（`02-architecture.md` Agent 形态、Q7、Q8、Q12），不进入 S1。
- 某份交接格式让 C 无法工作 → 先改交接格式，不在 C 里打补丁。
